# 掉落实现与验证关口

新建或重构走完整流程；局部修复核实当前输入后，只执行受影响步骤和相关回归。继承已核实且未变化的证据，不要求重做人物模型。检查结果可写进项目现有报告，不强制新建固定名称的文件。

## 1. 核实实际输入

记录工作区与游戏目标 addon、实际注册模型、生成入口，以及每个目标槽位的 bodygroup 名称/索引/穿戴态/隐藏态、左右骨骼、独立 prop 与 skin 映射。以成品或实际工程为证，不从示例猜数值。

列出本功能消费者：伤害 hooks、尸体创建与接管入口、bodygroup 覆写、客户端同步、拾取和清理。核实当前运行配置，区分“预算允许掉两件不同装备”和“同一槽位重复生成”。存在相关尸体插件时，读取它的实际创建入口；不能假定一定触发标准 CreateEntityRagdoll。仅在本任务确需兼容时适配，不自动引入第三方依赖或修改第三方插件。

输出证据：实际路径与源码位置、槽位映射、入口清单，以及尚未核实的内容。关键映射缺失时先补证，不能以原点生成等兜底冒充可用。

## 2. 确定状态与事件方案

选择本次触发模式、概率和事件总预算。读取共享状态、客户端、对应模式及适用的多装备参考。允许等价实现，不要求照抄模板函数名，但必须保持以下行为：

- 尸体绑定创建时的生命记录和槽位快照；后续尸体受伤不能重新取玩家当前生命记录。重生、换模或原拥有者移除后，旧尸体按明确策略独立保留或停止掉落，不能修改新身体。
- 同一生命、同一槽位最多一个有效掉落物。创建前预留，成功后登记并提交隐藏状态，失败时释放预留并恢复；同一受击的重复回调共享概率、预算和重入保护。装备已掉落但物品被清理时，不得仅因登记实体无效就重新视为穿戴。
- 生成、穿戴隐藏、尸体快照、客户端显示和拾取消费同一权威状态。外部设置 bodygroup 时有明确的状态更新或让渡方式，不能单靠 Think 不断覆盖掩盖冲突。
- 左右独立装备使用各自实际骨骼；骨骼不存在或位置无效时跳过该槽位并报告，不回退实体原点。道具原点偏移与朝向按实际资源验证。

输出证据：状态归属、死亡到尸体的交接、重生/换模/热重载策略。保留已有玩家选择，不为修复擅自改变事件预算或默认穿戴。

## 3. 实现并验证受影响行为

修改已有生成器及运行文件，避免重建覆盖修复。复用项目测试；缺少测试时，为涉及的状态转换增加最小可执行用例，测试实际 Lua 状态逻辑，不另写一份 Python 算法代替它。

按改动选择场景；新建或重构覆盖全部适用项：

| 场景 | 可观察断言 |
|---|---|
| 同帧重复伤害、生成期间重入 | 概率与总预算不重复消耗；每个槽位最多一个实体 |
| 爆炸致死并创建尸体 | 成功生成的槽位在身体/尸体隐藏；尸体继承同一生命状态 |
| 重生后攻击旧尸体 | 不使用新生命预算、不隐藏新身体、不借新生命重复生成旧装备 |
| 模型切换、拥有者移除 | 旧状态不污染新模型；尸体及掉落物按既定策略处理 |
| 骨骼缺失、生成/物理失败、下一帧实体失效 | 不从原点生成；无孤立预留；状态按失败策略恢复 |
| 拾取、物品过期或移除 | 拾取恢复原状态并先注销再删除；清理不等于重新穿戴 |
| 左右装备及不同 skin | 正确侧定位、隐藏、恢复和配色 |
| 冷启动、热重载、客户端晚加入 | 初始化幂等、无残留竞争 hook，当前尸体状态可同步 |

记录测试命令、输入版本、断言和结果。不能执行的项目写明原因及复测方式。Lua 隔离测试不证明引擎骨骼、网络时序或渲染正确；字符串检查不称为 Lua 测试。没有真实引擎时可交付待实机候选，不虚报通过。

## 4. 核对交付

仅在已有授权范围部署。部署前确认目标并保留必要回退；部署后逐项比较本次运行文件及必要模型资源的源/目标相对路径和 SHA256。不一致就纠正或报告未部署，不能以工作区通过替代游戏版本。

交付分别列出：静态检查、Lua 状态测试、部署一致性、真实 GMod 验证。给出最少实机步骤：爆炸存活/致死、确认对应部件隐藏及每槽位实体数量、拾取、复活后攻击旧尸体；按本次范围增减。未操作游戏就标记待实机确认。

## 技能维护时的行为评测

大幅修改此流程时，用隔离样例评测执行者：提供实际槽位资料、非标准尸体创建入口、左右装备、旧部署版本及可执行状态测试，要求完成一次爆炸掉落修复。评测提示不泄露预设缺陷或答案。检查最终行为与证据，而非是否写出特定标题：能否找到实际入口、隔离旧尸体生命、阻止重复、正确定位，并识别部署差异。未运行评测时明确记录，不能把新增用例说明称为评测通过。
